Two medium-priority problems and one documentation discrepancy remain.

## 1. An empty segment can overwrite another segment's permissions

Code: `libs/elf/src/lib.rs:173` and `boot/src/main.rs:168`.

`check_no_overlap` skips segments with `memsz == 0`, but AriBoot iterates over and maps every segment. If an empty segment has an unaligned address, `page_range()` returns a full page. A later empty segment can therefore overwrite the `.text` page table entry with RW/NX permissions, even though entry point validation passed.

Reproduction performed: keep the kernel's three original segments and add a fourth PT_LOAD with `vaddr = e_entry`, `filesz = memsz = 0`, RW flags and alignment 1. The loader accepts the ELF, exits boot services and the CPU page faults when trying to execute `0xffffffff80001ba0`; QEMU hits the six-second timeout. The original kernel contents remain intact.

Proposed fix: consistently ignore empty segments during loading, range computation and mapping, or reject them explicitly. Add a scenario with an unaligned empty segment over the entry page; if ignoring is chosen, it should boot exactly like the original ELF.

Evidence: `empty-segment/serial.log` and `empty-segment/esp/aricodeos/kernel.elf` next to this report.

## 2. Lexical name validation does not prevent escaping through a symbolic link

Code: `tools/xtask/src/image.rs:31` and `:43`.

A valid name such as `boot.probe` passes `validate_name`, but if `build/scenarios/boot.probe` is a link to another directory, `remove_dir_all` receives a path whose intermediate component is that link. Deleting `esp` and the subsequent copy happen in the target outside the scenarios tree.

Reproduction performed against the original `image.rs` functions, using only throwaway files created for this review: a link from `build/scenarios/boot.probe` to a sibling directory made its `esp/marker` file disappear and created `esp/aricodeos/kernel.elf` there. The function returned `Ok`. The entire reproduction stayed inside `build/audit/recheck`; no unrelated data was touched.

It requires a pre-existing link in the path; it does not mean the current nominal scenarios delete external data on their own.

Proposed fix: reject symbolic components and check actual containment of the target before deleting/writing. If resistance to concurrent path changes is intended, use directory-descriptor-relative operations instead of relying only on prior checks. Add a regression test that preserves a sentinel file outside `build/scenarios`.

Evidence: `xtask_probe.rs`, `xtask-probe.log` and the `fixture-*` folder next to this report. The harness imports the original `image.rs` and `scenario.rs` modules; it only replaces the root paths and the OS build, which it does not use.

## 3. The resolution claims a validation on TOML load that does not exist

Document: `docs/audits/2026-09-26-audit-42d4c57.md:97`.
Code: `tools/xtask/src/scenario.rs:106`.

`load_all()` deserializes, checks the level and adds the scenario without calling `validate_name`. The reproduction returns `Ok("../escape")` for a TOML with that name. Validation does run in `image::scenario_dir` before a scenario is processed, so this detail does not by itself reopen the original deletion path with `..`.

Fix the implementation to validate on load and cover that path with a regression test, or adjust the document to what the code actually guarantees.

# Resolution (branch `fix/audit-recheck-3a983e0`)

| # | Finding | Fix | Regression |
|---|----------|------------|-----------|
| 1 | Empty segment clobbers permissions | `Elf::parse` drops `PT_LOAD` segments with `memsz == 0` after validating them, so reservation, copy and mapping never see them; `check_no_overlap` no longer needs to filter them. An ELF whose only segment is empty yields `NoSegments`. | `libs/elf`: `empty_segments_are_dropped_and_cannot_clobber_text`; QEMU: `boot.loader_ignores_empty_segment` (injection `add_empty_segment_at_entry`, must boot exactly like the original ELF) |
| 2 | Symbolic link in the path | `image::scenario_dir` receives the scenarios root, canonicalizes it, rejects the scenario directory or its `esp` being symbolic links (`symlink_metadata`) and checks that the final canonical path is still inside the root, all before `remove_dir_all`. | `xtask`: `symlinked_scenario_dir_is_rejected_and_outside_data_survives` (external sentinel preserved), `symlinked_esp_is_rejected`, `nominal_scenario_esp_is_built_inside_root` |
| 3 | Missing validation on load | `scenario::load_from` calls `validate_name` for each TOML; `load_all` is a wrapper over `tests/qemu/`. The previous document's claim becomes true. | `xtask`: `load_rejects_invalid_names` |

Verification: `cargo xtask check` and `cargo xtask test --all` (33 unit tests, 6 QEMU scenarios) green.

Note on finding 2: the check happens before the operation and does not withstand a race with another process that creates the link between the check and the deletion. The xtask is a local single-user tool; if it ever runs in a shared environment, it will need to move to directory-descriptor-relative operations, as the review suggests.
