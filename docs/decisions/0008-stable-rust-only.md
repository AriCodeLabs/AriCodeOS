# ADR 0008: Stable Rust only; interrupt stubs in generated assembly

- **Date:** 2026-09-26
- **Status:** Accepted

## Context

Exception handlers in Rust are usually written with the
`extern "x86-interrupt"` ABI, which is still unstable (it requires nightly).
The project pins the toolchain in `rust-toolchain.toml` and wants
reproducible builds without depending on a specific nightly.

## Decision

AriCodeOS builds only with stable Rust. The 256 interrupt stubs and the
common trampoline are assembly (`kernel/src/arch/x86_64/stubs.s`)
included with `global_asm!`, generated by `tools/gen-stubs.py` and versioned.
The dispatch logic is in Rust (`interrupt_dispatch`) and receives an
`InterruptFrame` with a `repr(C)` layout that mirrors exactly what the
trampoline pushes.

## Alternatives

- `extern "x86-interrupt"` on nightly: less code, but it ties the project
  to the unstable channel and to ABI changes.
- `naked` functions (stable since 1.88): viable, but 256 Rust functions
  each with its own `asm!` are less readable than a generated table.

## Consequences

- Any change to the stack frame is made in two places: the generator and
  `InterruptFrame`. The scenarios of the `interrupts` area detect mismatches.
- The architecture structures (descriptors, TSS, IDT) live in
  `libs/x86-cpu` and are tested on the host; the kernel only executes the
  privileged instructions.
